# Embedded provider configuration

`lib/data/provider_addresses.dart` contains the operator-controlled portal, currently `http://167.235.169.168`, exposed through `lib/core/provider_config.dart`. Login and pre-login connection diagnosis construct credentials from this constant and the entered username/password. API requests and generated Live TV, movie and episode stream URLs use the current session's configured IP. No editable server field or provider URL is shown in Settings. API/player errors and exported diagnostic reports omit addresses; configuration repair instructions refer customers to support.

This is interface configuration, not a secrecy boundary: an embedded address can be recovered from an APK or network traffic. The configured HTTP portal also uses HTTP for API/stream URLs; hiding its address does not encrypt the connection. HTTPS can be enabled by changing the operator constant when the provider supports it.

At startup, sessions already using the configured IP are retained. The specifically approved previous portal `http://liquidmetal.vip` is migrated to the new IP and written back to encrypted storage. Its old address remains only as a migration marker and canonical storage identity; no network fallback uses it. The IP-based account retains the previous account ID for the same username, including after re-login or account refresh, preserving history, preferences, favourites, parental PIN and cache. Unrelated saved portals are signed out without deleting their history or forwarding their credentials.

Expiry parsing is shared by account display, sign-in and diagnostics. `exp_date: null` on an authorized Active/Unlimited line is treated as Xtream's no-expiry value, distinct from an absent key. Explicit unlimited/lifetime markers are also supported. A real date takes precedence. Missing/invalid information and connection-count limits are not treated as lifetime subscriptions. Account authorization, inactive status and expired timestamps are still enforced.
