# Streamline 0.5 design and behaviour

Midnight blue surfaces, cool-white display type and cyan selection accents unite a cinematic movie library with a television-focused live experience. An optional Cinema palette uses neutral black and ivory. Both retain the same visual hierarchy.

The five main destinations are Home, Live TV, Movies, Series and Settings. TV uses an icon rail which expands when focused. Mobile uses a five-item bottom bar. Home combines a provider-backed featured film, Continue Watching, personal recommendations, recently added films, My List and favourite channels. Live TV pairs channel selection with a large programme/artwork preview and Now/Next information, with the time grid a single action away.

Movie shelves use taller artwork and clear, consistent spacing. Focus uses an outline and restrained scale. Large-poster, compact-layout and reduced-motion preferences affect the actual interface. Settings use grouped cards and a wide two-column layout when space permits, with all options reachable on shorter screens.

Player chrome is a compact floating transport and secondary action row. It fades out after five seconds of playback by default, taking the title, branding and gradient with it. Subtitles remain visible near the bottom. Tap/OK reveals chrome; a second OK on the surface controls playback. Back closes menus, then visible chrome, then playback. Errors, pause, open menus and the next-episode countdown remain actionable.

Preferences, browsing state, category visibility, parental restrictions and player overrides belong to each provider/account. PINs use salted PBKDF2 in encrypted secure storage with attempt throttling. Protected categories are excluded from Home, recommendations and guide browsing until unlocked; direct playback also checks protection. Backgrounding locks the session again.

Recommendations use meaningful movie playback (at least one minute and five percent), weighted by recency and progress. Provider categories determine similarity; supplied ratings break close ties. Watched titles, duplicate editions, unavailable, hidden and locked content are excluded. Labels explain the watched source. No collaborative or AI claims are made, and viewing history is not sent to a recommendation service.

Reviewable phone and TV previews are generated from the real Flutter components in build/qa during UI verification.
